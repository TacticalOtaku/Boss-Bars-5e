Спека: [§2–4, §11, §14, §16 строка 1](../spec.md#16-этапы). Тикеты: [#8 Модель данных](https://github.com/TacticalOtaku/Boss-Bars-5e/issues/8),

## Результат (версия 0.2.0)

ГМ открывает профиль босса с HUD токена или из меню ⋮ листа актёра и заполняет вкладку «Основное». Потом он показывает
полосу кнопкой на HUD или из панели «Активные боссы». Полоса компоновки A в облике «Классика RPG» видна у всех клиентов:
заливка считается из данных актёра, а светлый след урона догоняет её. Несколько боссов складываются стеком.
Игрок не видит токен, скрытый ГМом, а сам ГМ видит такую полосу приглушённой. Поражение видно на полосе.
Игрок может свернуть полосу. Числа ХП видит только ГМ.

Не входит в этап (по спеке позже): элита и «×N» (2), раскладка и якоря (3), автопоказ, статусы и мини-полосы (4),
эффекты урона с силой по %, облики и пресеты (5), фазы и засечки (6), фразы (7), музыка (8), публичное API (11).

## Данные

Все схемы проходят через `core/`: чистые функции разбора, проверки и миграции с тестами в Node. У каждой схемы есть
`dataVersion: 1`. Неизвестные ключи при записи сохраняются. Данные более новой версии показываются, но не
перезаписываются: автоматическая запись их пропускает, ручная выдаёт уведомление (решение старого модуля, §6).

**Профиль босса** — `actor.flags["boss-bars-5e"].profile` у **базового** актёра:

```ts
{ dataVersion: 1, kind: "boss", playerName: string, title: string, portrait: string | null, size: number }
```

`portrait: null` означает картинку актёра. Поддерживаются img, GIF, WebP и webm/mp4 (`<video muted loop autoplay>`).
`size` — размер в %. Поля режима показа, режима заливки, засечек, мини-полос и прочего появятся вместе со своими
этапами.

**Экземпляры** — `scene.flags["boss-bars-5e"].instances`:

```ts
{ dataVersion: 1, items: [{ id: string, kind: "boss", tokenId: string, order: number }] }
```

`order` — порядок показа: стек идёт по нему. Повторный показ того же токена ничего не меняет.

**Свёрнутость** — клиентская настройка `collapsed`: `{ [sceneId]: string[] }` (id экземпляров).
**«Игроки могут сворачивать»** — мировая настройка `playersMayCollapse`, по умолчанию включена.

### Сигнал ХП и пересчёт

`store.ts` слушает следующие хуки:

- `updateActor`: и для базового, и для синтетического актёра несвязанного токена;
- `updateToken`: `hidden`, имя, дельта;
- `create`, `update` и `delete` для `Item` и `ActiveEffect`: от них меняется `effectiveMax`;
- `updateCombatant` (`defeated`), `deleteToken`, `updateScene` (флаги), `canvasReady` (смена сцены и уровня);
- `updateSetting`: настройки модуля.

После любого из этих хуков он пересчитывает вид в микрозадаче. Хуки урона dnd5e не используются ([ADR 0001](../adr/0001-hp-signal-from-data.md)).

### Полоса

- Заливка и след меняются через `transform: scaleX()`. След догоняет заливку с задержкой. Лечение двигает заливку
  без следа. При первом показе и при F5 полоса встаёт сразу на место, без анимации.
- Вход и уход полосы — только `opacity` и `transform`. Уходящая полоса остаётся в DOM до конца анимации. Если её
  снова показали во время ухода, она возвращается.
- При уменьшенном движении (`prefers-reduced-motion` или `body.performance-low`) остаются только смены прозрачности.
- Подпись: имя для игроков, если оно задано, иначе имя токена. Нумерация одинаковых имён — в этапе 2.
- Числа `value / effectiveMax` (+ временные) рисуются только у ГМа: модель вида игрока их не содержит. ARIA:
  `role="meter"`, `aria-valuenow` — процент заливки.
- Тексты выводятся через `textContent`, id из флагов сравниваются по значению атрибута и не подставляются в
  селекторы.
- Стек (до этапа 3): блок по центру сверху `#interface`, отступ 16 px, полосы идут вниз. Размер в профиле и масштаб
  `core.uiConfig.uiScale` (берётся из настройки, а не из CSS-переменной) задают ширину.

### Авторитет

- `show`, `hide`, `hideAll` и `removeProfile` — действия, которые только активный ГМ проверяет и записывает.
- Без активного ГМа запись отклоняется с уведомлением. Заливка и поражение при этом продолжают считаться на каждом
  клиенте.
- Удалённый токен убирает свой экземпляр: это автоматическая запись, её делает только активный ГМ.
- Снятый профиль скрывает экземпляры актёра на всех сценах. Копия токена на другой сцене сама не показывается.

## Порядок работы (TDD для core/)

1. `core/schema`, `profile`, `instances`, `actions`, `hp`, `defeat`, `view` — тест, потом код.
2. `integrations/dnd5e/actor.ts`: тесты на фикстурах формы данных 5.3.3, то есть связанного и несвязанного токена,
   `tempmax` и `effectiveMax = 0`.
3. Настройки, `authority` (тест с заглушками `game.users`: активный ГМ, неактивный ГМ, игрок, нет ГМа), `store`.
4. `ui/boss-bar`, `boss-stack` + SCSS «Классика RPG»; стенд на фикстурах.
5. HUD токена, меню ⋮, контролы сцены.
6. Редактор профиля и панель (Handlebars-шаблоны проверяются в тестах разбором).
7. Ключи en и ru, `CHANGELOG`, версия 0.2.0, модульный `CLAUDE.md`.
8. `npm run check > log && npm run deploy`, `npm run release`.
9. Живая проверка.

## Живая проверка (мир `test`, 14.367 / 5.3.3, ГМ `Claude` + игрок `Claude 2`)

1. F5 у обоих, фон ошибок до и после.
2. ГМ открывает профиль с HUD токена и из меню ⋮ листа, заполняет «Основное» и сохраняет. Профиль лежит у базового
   актёра, в том числе для несвязанного токена.
3. ГМ показывает полосу кнопкой HUD. Полоса есть у обоих, у игрока в DOM нет чисел ХП.
4. `actor.update` ХП (урон и лечение) у связанного и несвязанного токена: заливка у обоих совпадает с
   `value / effectiveMax`, след догоняет.
5. Второй босс встаёт в стек ниже. F5 — стек и состояние на месте.
6. ГМ скрывает токен: у игрока полосы нет, у ГМа она приглушена.
7. Поражение тремя способами: 0 ХП, статус `dead`, отметка «повержен» в трекере.
8. Игрок сворачивает полосу. После F5 она свёрнута, на другой сцене — нет. Выключенный `playersMayCollapse` убирает
   кнопку.
9. Панель «Активные боссы»: показать и скрыть, «Скрыть все».
10. Удаление токена убирает экземпляр. Снятие профиля скрывает полосы.
11. Игрок вызывает запись через консоль (`authority`): отказ и уведомление, в мире ничего не меняется.
12. Изменённые настройки вернуть, тестовые данные — по решению ниже.

## Решения (2026-10-25, «Всё да»)

1. Редакторы — вид листа AIM, значения переписаны в свои токены `--bb5e-*` на корне окна; файлы Tactile, Onest и
   Unbounded не подключаются, шрифт — интерфейсный шрифт Foundry.
2. Одна кнопка на HUD токена: без профиля клик открывает редактор; с профилем клик показывает или скрывает полосу,
   правый клик открывает профиль.
3. Поражение: пустая приглушённая полоса остаётся, пока ГМ её не скроет; автоскрытие — этап 4.
4. Сворачивание: кнопка ▾, свёрнутая полоса — имя и тонкая заливка; своё на каждой сцене; «Игроки могут
   сворачивать» — пункт настроек модуля (по умолчанию включён), на этапе 3 переезжает в панель раскладки.
5. Стек до этапа 3: по центру сверху `#interface`, отступ 16 px, вниз; ширина — размер профиля × `uiScale`.
6. Панель: все токены текущей сцены с профилем босса, переключатель «показан / скрыт», «Скрыть все».
7. «Основное»: имя для игроков, титул, портрет, размер 50–200%.
8. «Убрать профиль» с подтверждением; полосы актёра скрываются на всех сценах.
9. «Профиль босса» в меню ⋮ листов NPC и персонажей, только ГМ.
10. Папка «Boss Bars QA» с двумя NPC (связанный и несвязанный токен) остаётся в `test`; один коммит после «да»,
    без push.
