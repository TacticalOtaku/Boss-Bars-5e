# План этапа 2 — колонка элиты и ранги

Спека: [§2, §4, §5, §11, §16 строка 2](../spec.md#16-этапы). Тикеты: [#8 Модель данных](https://github.com/TacticalOtaku/Boss-Bars-5e/issues/8),

Макеты: `prototype/hud-variants` (карточки A, ранги), `prototype/editors` (экраны «Профиль элиты» и «Ранги»).

## Результат (версия 0.3.0)

- ГМ делает актёра элитой в том же окне профиля (переключатель «Босс / Элита») и выбирает ему ранг.
- Карточки элиты стоят колонкой слева, отсортированы по рангу. Каждая карточка показывает ровно те части, которые
  разрешает её ранг.
- Ранги ГМ правит в окне «Ранги элиты» с живой карточкой у каждого ранга.
- У боссов и у элиты есть режим «одна на актёра»: одна полоса или карточка на все токены актёра на сцене, с «×N».
- Одинаковые имена на сцене нумеруются.
- Панель «Активные боссы» показывает и элиту.

Не входит в этап: облик ранга и «Мастерская обликов» (этап 5), статусы на карточке и мини-полосы (этап 4),
раскладка, якоря и «сколько карточек видно» в панели раскладки (этап 3), автопоказ (этап 4).

## Данные

**Версии схем** становятся раздельными, у каждой схемы своя. Профиль и экземпляры переходят на `dataVersion: 2`, и
появляется первая миграция v1 → v2. Модуль 0.2.0 увидит данные 0.3.0 как «более новые» и не испортит их: старый
читатель молча выкинул бы экземпляры элиты при первой же записи.

**Профиль** (`actor.flags.boss-bars-5e.profile`, v2) — один на актёра, вид задаёт поле `kind`:

```ts
// общее
{ dataVersion: 2, kind: "boss" | "elite", playerName, portrait, displayMode: "token" | "actor" }
// босс: + title, size        элита: + rank (id ранга)
```

- Миграция v1 → v2 добавляет `displayMode: "token"`.
- При смене вида поля другого вида остаются во флаге как неизвестные ключи. Обратное переключение их возвращает.
- Если ранг элиты удалён, она берёт самый слабый ранг.

**Экземпляры** (`scene.flags.boss-bars-5e.instances`, v2):

```ts
{ id, kind: "boss" | "elite", tokenId?: string, actorId?: string, order }
```

- Ровно одно из `tokenId` или `actorId`: режим «на токен» или «на актёра».
- Миграция v1 → v2 ничего не меняет в элементах, только поднимает версию.
- Показ идемпотентен по ключу: тот же токен или тот же актёр второй раз не показывается.

**Ранги** — мировая настройка `ranks` (v1):

```ts
{ dataVersion: 1, items: [{ id, name, color, parts: { name, fill, statuses }, size }] }
```

- Порядок в списке и есть сила ранга: сверху сильнее. Иконка на карточке есть всегда.
- `size` — сторона иконки в px, от 24 до 64.
- Пока ГМ не сохранил свои ранги, действуют 4 ранга по умолчанию из макета (Капитан, Ветеран, Боец, Страж), их
  имена идут из перевода.

## Режим «одна на актёра»

- Экземпляр привязан к актёру. В него входят все его токены на сцене.
- `N` — число токенов; ГМ считает все, игрок — только видимые ему.
- ХП несвязанных токенов складываются.
- Связанные токены делят одного актёра, поэтому их ХП считаются один раз.
- Поражение наступает, когда повержены все токены. Экземпляр скрыт от игрока, если скрыты все токены.
- Автоочистка убирает экземпляр, когда на сцене не осталось токенов актёра.

## Нумерация

- Имена сравниваются по итоговой подписи (имя для игроков или имя токена или актёра) среди всех показанных
  экземпляров сцены: боссов и элиты.
- Первый носит имя без номера, следующие — «Имя 2», «Имя 3» по порядку показа.
- Сначала нумеруются нескрытые экземпляры, потом скрытые. Так номера, которые видит игрок, не выдают скрытых
  противников и одинаковы у ГМа и игрока.
- Чистая функция в `core/labels.ts` с тестами.

## Живая проверка (мир `test`, ГМ + игрок)

1. Фон ошибок до и после.
2. Данные этапа 1 читаются после миграции: профили и экземпляры v1 → v2 без потерь.
3. Профиль элиты: переключатель вида, ранг, превью. Возврат к боссу возвращает его поля.
4. Колонка: 4 ранга — порядок и части карточек верные, у игрока нет чисел.
5. «На актёра» для несвязанного (×3, сумма ХП) и связанного токена (ХП один раз).
6. Нумерация: три «Орк-берсерк» → без номера, 2, 3; скрытый не сдвигает номера у игрока.
7. Редактор рангов: порядок ↑↓ пересортировывает колонку у всех, части и размер меняются, удаление ранга.
8. Лимит карточек и «+N».
9. Панель: элита показывается и скрывается.
10. Регрессия этапа 1: полоса босса, след, сворачивание.

## Решения (2026-10-25, «Всё да»)

1. Ранги по умолчанию — 4 из макета, имена из перевода, пока ГМ не сохранил свои.
2. «×N»: ХП связанного актёра считается один раз, несвязанных — складываются; N — число токенов.
3. Нумерация: первый без номера, дальше 2, 3 по порядку показа, общая для боссов и элиты; сначала нескрытые.
4. Колонка до этапа 3: слева, по центру по вертикали, x = 104 px, ширина 230 px × `uiScale`, вниз.
5. Видно 12 карточек, остальные — «+N»; число настраивается на этапе 3.
6. Удаление занятого ранга — с подтверждением и числом актёров; элита без ранга берёт самый слабый.
7. Порядок рангов — кнопки ↑↓, без перетаскивания.
8. При смене вида поля другого вида сохраняются во флаге.
9. Числа ХП у ГМа — в строке имени; у карточки «только иконка» — во всплывающей подсказке.
10. Профиль и экземпляры — v2 с миграцией; галочка «статусы» есть, рисуются с этапа 4; QA: «QA Орк-берсерк»
    (несвязанный, ×3) и «QA Волк» (связанный, ×2); один коммит после «да».
