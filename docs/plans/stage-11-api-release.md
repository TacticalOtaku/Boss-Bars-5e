## API

Ссылка на полосу (`instance`) — id экземпляра, запись из `getActive` или токен (`Token` / `TokenDocument`: полоса,
которая его покрывает). Не нашлась — отказ `BB5E.Error.NoInstance`.

| Метод | Поведение |
|---|---|
| `show(token \| actor, { sceneId? })` | Токен — его полоса или карточка. Актёр — его токены на сцене (по умолчанию просматриваемой): «на актёра» — одна полоса, «на токен» — каждая. Уже показанное — успех без записи |
| `hide(instance)`, `hideAll(sceneId?)` | Как кнопки панели; `hideAll` по умолчанию — просматриваемая сцена |
| `setPhase(instance, phase)` | id фазы или её номер с 1; форма и ожидание — как при выборе фазы в панели |
| `say(instance, quoteOrText)` | Строка, равная id фразы профиля, — эта фраза (пул, курсор, без кулдауна); иначе — свой текст |
| `playEffect(instance, effect)` | `damage`, `heal`, `phase`, `defeat`; данные не меняются, см. ниже |
| `setCounter(instance, miniBarId, value)` | Только мини-полосы-счётчики; активный ГМ режет до максимума |
| `toggleStatus(instance, statusId, on?)` | Только свои статусы профиля; без `on` — переключить |
| `getActive(sceneId?)` | Только чтение, массив замороженных записей, см. ниже |
| `openEditor(actor)`, `openPanel()`, `layoutMode(on?)` | Только ГМ; `layoutMode` открывает или закрывает панель раскладки и возвращает её состояние |

- Методы записи идут через `requestWrite` (`foundry/authority.ts`); Promise разрешается после записи активным ГМом.
- **Ошибки**: `Error` с `code` — ключом `BB5E.Error.*` — и переведённым `message`. Новые коды: `NoInstance`,
  `NoToken`, `NoSuchPhase`, `NoQuote`, `NoCounter`, `NoSuchStatus`, `Cancelled`; активный ГМ бросает их вместо общего `Invalid`.
- Вызов игрока сразу отклоняется (`NotGM`) с уведомлением и никуда не уходит.
- **`playEffect`** — только ГМ. Сообщение модульного сокета всем клиентам (и себе); получатель проверяет, что
  отправитель — ГМ, полоса показана и эффект из списка. Полосы босса — все четыре; карточки элиты — `damage`, `heal`.
  `defeat` — баннер поражения и пепел «распада» один раз, полоса остаётся.
- **`getActive`** — то, что этот клиент видит в HUD:
  - у всех: `id`, `sceneId`, `kind`, `tokenId` / `actorId`, `label`, `fraction`, `defeated`; у босса `phase.label`,
    `quote` (текст на экране);
  - у ГМа ещё: `hp` (`value`, `max`, `temp`), `phase.id`, `phase.waiting`, `phases` (`id`, `label`), `quotes`
    (`id`, `trigger`), `counters` (`id`, `label`, `value`, `max`), `statuses` (свои: `id`, `label`, `active`);
  - у игрока нет полос скрытых токенов, чисел ХП, списка фаз и ожидания формы (тест, как у `core/view.ts`).
- API ставится в `init`; `boss-bars-5e.ready` (аргумент — API) — после монтирования HUD в `ready`.

## Хуки

- **`pre*`** — только у активного ГМа, внутри `apply` до записи, для любого источника: API, кнопки, автопоказ и
  автоскрытие. `preShow({ sceneId, tokenId, actorId, kind })`, `preHide({ id, sceneId, kind })`; в `hideAll` —
  на каждую полосу, отменённые остаются. Автоочистка удалённых токенов не спрашивает. `false` — отказ `Cancelled`.
- **Без `pre`** — на всех клиентах, из разницы флага `instances` до и после `updateScene` (чистая функция
  `core/events.ts`): `show` (новый id), `hide` (id исчез), `phaseChange` (сменился `phase.id`), `quote` (новый
  `quote.key`). Переход формы на другой токен — не hide/show; раненый босс, показанный сразу в фазе, — не
  `phaseChange`. После загрузки — только запоминание, без событий.
- **`defeated`** — переход в поражение по тому же правилу, что автоскрытие (0 ХП, статус, побеждённый участник боя;
  не пока форма впереди или ждёт), на всех сценах, после пересчёта; первый пересчёт после загрузки — база.
- Аргумент: `{ id, sceneId, kind }`, у `phaseChange` ещё `phase` и `previous` (`label`, у ГМа `id`), у `quote` —
  `text`. Игроку — только про полосы, которые он видит.

## Живая проверка (мир `test`, ГМ + игрок)

1. Фон ошибок; `api` заморожен, `version` 1, `ready` пришёл.
2. Каждый метод под ГМом: показ токена и актёра, скрытие, фаза по id и номеру, фраза по id и текстом, счётчик,
   статус, эффекты на полосе и карточке; ошибки с кодами.
3. Под игроком: методы записи отклонены с уведомлением, `getActive` без скрытого.
4. Хуки на обоих клиентах; `preShow` / `preHide` с `false` отменяют показ из панели и автопоказ.
5. Восстановление WebGL-контекста (контекст ловится обёрткой `drawArrays`, `WEBGL_lose_context`).

7. Облик на ранге элиты.
8. Бюджет: 2 полосы с живыми заливками + 12 карточек — в покое и под уроном; размер HUD.
9. Регрессия этапов 1–10.

## Решения (2026-10-26, «Всё да»)

1. Два захода с остановкой: API, хуки, ошибки и тесты; затем документы, бюджет, живая проверка и 1.0.0. Коммит
   один, в конце.
2. Ссылка на полосу: id, запись `getActive` или токен; не нашлась — `NoInstance`.
3. `show`: токен — его полоса; актёр — его токены на сцене по режиму профиля; разрешается без значения; уже
   показанное — успех.
4. `setPhase` — id или номер с 1; `say` — id фразы профиля, иначе свой текст; id видны ГМу в `getActive`.
5. `toggleStatus` — только свои статусы, без `on` переключает; `setCounter` — только счётчики, до максимума.
6. `playEffect` — только ГМ, сокет всем клиентам с проверкой у получателя; карточки — `damage` и `heal`; `defeat` —
   баннер и пепел один раз.
7. `getActive` — поля как выше; у игрока только видимое, без чисел, фаз и ожидания (тест).
8. Ошибки — `Error` с `code` и переведённым `message`; новые коды; уведомление и игроку, и ГМу.
9. Хуки без `pre` из разницы флага на каждом клиенте; форма — не hide/show; раненый показ — не `phaseChange`; после
   загрузки событий нет; игроку — только видимое.
10. `pre*` для любого источника, в `hideAll` на каждую полосу; автоочистка не спрашивает; `false` — `Cancelled`.
11. `defeated` — правило автоскрытия, все сцены, только переход, база после загрузки.
12. Размер в `npm run check` (≤ 100 КБ gzip); fps — трассировка Chrome DevTools под `Claude 2`.
13. WebGL-восстановление — обёрткой `drawArrays` в пилоте; музыка со сменой сцены — только с разрешения в тот
    момент; облик ранга элиты; README и API.md на английском без скриншотов; CHANGELOG и 1.0.0.

## Итоги (2026-10-26)

- **Размер**: HUD-скрипт (вход + статические импорты, 6 файлов) — 68,4 КБ gzip из 100; проверка в `npm run check`.
- **Замер fps** — Chrome 156, RTX 5070, экран 165 Гц, игрок `Claude 2`, 1600×900; 2 полосы с живой заливкой
  («Неон») + 12 карточек элиты:
  - покой: 165 fps, худший кадр 6,3 мс;
  - нагрузка (ГМ меняет ХП обоих боссов и 4 элит каждые 0,4 с, ~15 обновлений актёров в секунду, плюс
    `playEffect`): 142,6 fps, p95 6,5 мс, кадров длиннее 16,7 мс — 3,5 %, худший 61 мс;
  - та же нагрузка без полос: 162,5 fps, p95 6,2 мс, 4 кадра длиннее 20 мс.
  - Трассировка нашла принудительную раскладку каждый кадр в цикле живой заливки (`clientWidth` после эффектов ХП,
    228 мс за 6 с): размеры теперь приходят из `ResizeObserver`, p95 под нагрузкой — с 12 до 6,5 мс. Оставшиеся
    длинные кадры совпадают с обработкой обновлений документов Foundry (~13 мс на задачу); доля модуля в ней
    ~2–3 мс, копирование кадров живой заливки ~0,1 мс на полосу. Анимации HUD — только `transform`.
- **WebGL**: потеря контекста в Foundry — CSS-заливка сразу, восстановление — снова живая, кадры рисуются, ошибок GL
  нет.
- **Облик ранга элиты** в Foundry: карточки в облике ранга («Неон»: шрифт, компоновка, заливка).
- **Музыка со сменой активной сцены** (с разрешения пользователя, временные сцена и плейлист удалены): активной стала
  пустая сцена — музыка босса затухла, трек мира продолжился, снимок пуст; вернули сцену с боссом — его музыка снова
  играет; `fade` треков вернулись к исходным; игрок перешёл вместе со сценой.
- Регрессия: показ, ХП, карточки, вид игрока без чисел — как в 0.11.0.
